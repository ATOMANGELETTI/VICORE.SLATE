# Phase 1: Governance, Root Foundation & Tooling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the complete `.cursor/` agent-governance layer, the `.superpowers/` artifact-redirection convention, and every root-level workspace/tooling file (Bun, moon v2, Cargo workspace, Biome, Rust lint/format/deny, Changesets, Husky+Commitlint, CI, toolchain pinning) so every later phase inherits a working, lint-clean, buildable-but-empty monorepo skeleton.

**Architecture:** Two layers, created in strict order because later rules assume the redirection rule already governs agent behavior: (1) `.cursor/rules/*.mdc` + `.superpowers/` — pure documentation, no code; (2) root workspace files — `package.json`, `Cargo.toml`, `.moon/`, lint/format configs, CI, git hooks, Changesets, toolchain pins. Globs in `Cargo.toml`/`package.json`/`tsconfig.json`/`vitest.workspace.ts` mostly resolve to zero matches until Phase 2 (Shared Packages) and Phase 3 (Apps) populate `packages/`, `crates/`, and `apps/` — this is expected and verified explicitly per task.

**Tech Stack:** Bun 1.4, moon v2, Cargo/rustup, Biome, rustfmt/clippy/cargo-deny/cargo-mutants/tarpaulin, Husky + Commitlint (Conventional Commits), Changesets, mise (`.tool-versions`), GitHub Actions.

## Global Constraints

- Bun only — never `npm`/`yarn`/`pnpm` in any script, doc, or CI step.
- Every automation script is Bun-executed TypeScript (`scripts/*.ts`), never `.ps1`/shell-only.
- Dot-segmented names for multi-axis variant files (e.g. `tauri.windows.conf.json`) — established convention, referenced by rules in this phase, first applied to real files in Phase 2/3.
- All test code lives under `tests/` — this phase's only real test is for `scripts/sync-crate-versions.ts` (Task 15), which goes in `tests/unit/sync-crate-versions.test.ts`.
- `.superpowers/{docs,plans,specs,sdd}/` is the only destination for Superpowers-generated artifacts, committed to git (not ignored).
- No deprecated/legacy tool versions — pin whatever `bun add -D <pkg>@latest` / `cargo add` resolves to at execution time, not a number guessed today.

**Later phases (not covered by this plan):** Phase 2 — Shared Packages (`packages/config-typescript`, `packages/config-vite`, `packages/ui-kit`, `crates/slate-core` stub). Phase 3 — Template Apps x9 (generator-first: `scripts/new-app.ts` + `scripts/templates/app/`, then generate all 9, then hand-patch `slate-launcher`'s tray/isolation extras). Phase 4 — Release Packaging + remaining `scripts/` automation + full-graph verification.

```markdown
# Monorepo & Naming Conventions

## Tooling

- Package manager: Bun workspaces (`apps/*`, `packages/*`).
- Orchestrator: moon v2 (`.moon/workspace.yml`, `.moon/toolchains.yml`,
  `.moon/tasks/*.yml`) — never a root `moon.json` or root `moon.yml`.

  dev through packaging (`apps/slate-terminal` -> `programs/slate-terminal/`
  at package time) — never renamed to `core-*`.

## Modular folders

- Apps: one module = one folder, nested under a `modules/` umbrella on both
  sides — TS `src/modules/<name>/`, Rust `src-tauri/src/modules/<name>/`.
- `packages/ui-kit`: keeps a type-based top split — `src/primitives/<name>/`
  (atoms: button, dialog, tooltip, ...) and `src/composites/<name>/`
  (shell-level: context-menu, titlebar, toolbar, app-shell). Each module
  still gets its own folder inside whichever bucket it belongs to.
- Component file naming: `<module-name>.tsx` inside its own folder, matching
  the folder name exactly.

## Dot-segmented variant files

Multi-axis variant files use `<domain>.<family>.<variant>.<ext>` —
e.g. `tauri.windows.conf.json`, `theme.nord.polar-night.css`,
`theme.nord.snow-storm.css`, `theme.nord.frost.css`, `theme.nord.aurora.css`.

## Per-module CSS override escape hatch

`src/styles/modules/<module-name>.css` for the rare case Tailwind utility
classes can't express something (complex keyframes, etc.) — imported by
that module's component. `src/styles/main.css` is the single entry point.
```

```markdown
  `rust-toolchain.toml` and `.moon/toolchains.yml` — CI fails the build if
```

```typescript
import { readFileSync, writeFileSync, readdirSync } from "node:fs";
import { join } from "node:path";

interface CrateManifest {
  version: string;
}

export function syncCrateVersion(crateDir: string): void {
  const pkgPath = join(crateDir, "package.json");
  const cargoPath = join(crateDir, "Cargo.toml");

  const pkg = JSON.parse(readFileSync(pkgPath, "utf-8")) as CrateManifest;
  const cargoToml = readFileSync(cargoPath, "utf-8");
  const updated = cargoToml.replace(
    /^version = ".*"$/m,
    `version = "${pkg.version}"`,
  );

  writeFileSync(cargoPath, updated);
}

export function syncAllCrateVersions(cratesDir: string): void {
  const entries = readdirSync(cratesDir, { withFileTypes: true }).filter(
    (entry) => entry.isDirectory(),
  );

  for (const entry of entries) {
    syncCrateVersion(join(cratesDir, entry.name));
  }
}

if (import.meta.main) {
  syncAllCrateVersions(join(import.meta.dir, "..", "crates"));
}
```

```typescript
import { readFileSync } from "node:fs";
import { parse as parseYaml } from "yaml";

export function parseToolVersions(content: string): Record<string, string> {
  const result: Record<string, string> = {};
  for (const line of content.trim().split("\n")) {
    const [tool, version] = line.trim().split(/\s+/);
    if (tool && version) result[tool] = version;
  }
  return result;
}

export function checkDrift(
  toolVersions: Record<string, string>,
  moonToolchains: Record<string, string>,
): string[] {
  const errors: string[] = [];
  for (const [tool, version] of Object.entries(toolVersions)) {
    const moonVersion = moonToolchains[tool];
    if (moonVersion && moonVersion !== version) {
      errors.push(
        `${tool}: .tool-versions has ${version} but .moon/toolchains.yml has ${moonVersion}`,
      );
    }
  }
  return errors;
}

if (import.meta.main) {
  const toolVersions = parseToolVersions(readFileSync(".tool-versions", "utf-8"));
  const toolchains = parseYaml(readFileSync(".moon/toolchains.yml", "utf-8")) as Record<
    string,
    { version: string }
  >;
  const moonToolchains = Object.fromEntries(
    Object.entries(toolchains).map(([k, v]) => [k, v.version]),
  );
  const errors = checkDrift(toolVersions, moonToolchains);
  if (errors.length > 0) {
    console.error(errors.join("\n"));
    process.exit(1);
  }
  console.log("Toolchain versions in sync.");
}
```
