# AGENTS.md

## Learned User Preferences

- Only latest/cutting-edge tools and dependency versions — never suggest or scaffold with old/legacy tech.
- Use a modular folder + file naming system throughout: one module = one folder (e.g. `src/context-menu/`, `src/titlebar/`), and dot-segmented names for multi-axis variant files (e.g. `theme.nord.polar-night.css`, `tauri.windows.conf.json`).
- All test code must live under an appropriate `tests/` directory (mirroring the module path) — never alongside implementation files.
- Prefer Bun over npm for all JS/TS tooling and scripts; automation scripts should be cross-platform Bun-executed TypeScript (`scripts/*.ts`), not `.ps1`/shell-only scripts.

## Learned Workspace Facts

- VICORE.SLATE is "Slate": a Bun + moon (v2) + Rust/Tauri v2 monorepo building a fully portable, thumbdrive/folder/drive-installable suite of AI-native desktop apps (a "portable AI operating system"). All dependencies, configs, and data are stored locally within the install directory — no OS user-profile paths.
- Monorepo layout: `apps/` = Tauri v2 applications (`slate-launcher`, `slate-terminal`, `slate-explorer`, `slate-browser`, `slate-editor`, `slate-gallery`, `slate-jukebox`, `slate-player`, `slate-aistudio`); `crates/` = shared Rust (`slate-core` stub only for now); `packages/` = shared TypeScript (`@slate/ui-kit`, `@slate/config-typescript`, `@slate/config-vite`).
- Frontend stack: React 19 + TypeScript + Vite + Vitest + Playwright + shadcn/ui built on Radix UI primitives (explicit choice over Base UI) + Tailwind CSS v4 (CSS-first `@theme`, no `tailwind.config.js`) + class-variance-authority + lucide-react.
- Design system (`packages/ui-kit`) strict boundary rule: ui-kit only holds what 2+ apps need identically (buttons, dialogs, window chrome/titlebar, base context-menu). Anything app-unique — even a modified context menu — is built in the app itself, optionally composing the ui-kit base module.
- Theme is the official Nord palette with all four families as separate dot-segmented token files: `theme.nord.polar-night.css` (dark surfaces), `theme.nord.snow-storm.css` (light surfaces/dark text), `theme.nord.frost.css` (accents), `theme.nord.aurora.css` (semantic status colors), aggregated by `theme.nord.css`. UI style is a modern flat, macOS-inspired design (no skeuomorphism/gradients/heavy shadows; flat surfaces, subtle 1px borders, soft rounded corners, translucent titlebar).
- Root tooling: Biome replaces ESLint/Prettier entirely for JS/TS lint+format; Rust uses `rustfmt.toml`/`clippy.toml`/`deny.toml`/`cargo-mutants.toml`/`tarpaulin.toml`; Husky + Commitlint enforce Conventional Commits; CI runs a Windows/macOS/Linux matrix via GitHub Actions.
- Every template app shares one skeleton: custom titlebar + window controls from ui-kit (`decorations:false` in `tauri.conf.json`), a content area showing "`<NAME>` Template Application" + live version (via `@tauri-apps/api/app` `getVersion()`), and a bottom toolbar shell from ui-kit with app-local toolbar content.
- Release packaging output (`installDir/`) is intentionally different from the dev-time monorepo layout and is assembled by `scripts/package.ts`: `launcher/` (built `slate-launcher`, top-level, not under `programs/`), `programs/core-<name>/` (the other 8 apps, `slate-` prefix dropped for `core-` in packaged output), `appdata/{configs,database,logs,docs,resources/{fonts,images}}`, and an empty `storage/` (per-profile subfolders are a deferred runtime concern, not created at package time).
- All project automation scripts live under root `scripts/` (`dev.ts`, `package.ts`, `new-app.ts`, `new-package.ts`, `new-crate.ts`, `templates/`); `.cursor/commands/*.md` are thin prompts that invoke these scripts rather than hand-scaffolding files.
- Explicitly deferred (documented in rules, not built yet): `crates/slate-runtime` (real portable-path resolution used at app runtime), per-profile `storage/<profile>/` creation at first run, any AI/LLM crate/package for `slate-aistudio`, an app registry/plugin-manifest format for the launcher, and persisted window state/single-instance plugin/auto-updater (all conflict with portability until the runtime crate exists).
- Superpowers-skill-generated artifacts (brainstorming specs, writing-plans output, docs, spec-driven-development artifacts) are redirected out of their scattered defaults into a single committed root folder: `.superpowers/{docs,plans,specs,sdd}/` — enforced by an always-apply `.cursor/rules/000-superpowers-plugin-paths.mdc` rule. This is distinct from the personal, git/cursorignored `.devlog/` folder.
- `.cursor/rules/` is numbered starting at `000-superpowers-plugin-paths.mdc`, followed by `001-project-overview.mdc`, `002-monorepo-and-naming.mdc`, and further numbered rules covering Rust/Tauri, TypeScript/React, ui-kit boundaries, app shell/window chrome, Nord theming, testing strategy, portability/deferred scope, git commit workflow, and release packaging layout.
- `AGENTS.md` is the canonical high-level project brief (architecture summary + pointers into `.cursor/rules/`); `CLAUDE.md` and `.cursorrules` are thin pointers to `AGENTS.md` for cross-tool compatibility.
